Core feature set

One focused workflow for player issues and staff decisions.

CoreCaseX keeps submissions, board filters, evidence, conversation, and final case outcomes connected inside one Paper plugin.

01

Guided submissions

Players open `/case` and use Paper Dialog forms instead of memorizing a large command tree.

02

Five case types

Support request, player report, bug report, lost items or death issue, and grief or theft flows.

03

Paper Dialog UI

Progressive menus, review screens, detail sections, option controls, hover text, and back actions.

04

Staff board filters

Staff can focus on open, unassigned, assigned, high priority, waiting, closed, or archived cases.

05

Ownership workflow

Claim cases, assign online staff, change priority or status, and keep ownership visible.

06

Replies and info requests

Staff replies, player replies, and request-more-info states keep the conversation structured.

07

Internal notes

Staff can record handoff context and observations without exposing internal discussion to players.

08

Evidence visibility

Evidence can be player-visible, staff-only, or sensitive, with dedicated permissions for access.

09

Timeline history

Creation, claims, assignments, replies, notes, status changes, resolutions, and archive actions are tracked.

10

Discord webhooks

Optional webhooks can mirror configured events with priority, case type, or default routing.

11

SQLite persistence

Cases, replies, evidence, notes, resolutions, migrations, and timeline events are stored locally.

12

Granular permissions

Separate player, staff, and admin permissions let owners shape real staff responsibilities.

Built for real servers

Designed for follow-up, ownership, and clear outcomes.

CoreCaseX is built for communities where support cannot live in chat scrollback. It gives staff a persistent view of what happened, who is responsible, and what needs action next.

Operational limits

Per-player open case limits and submission cooldowns help keep case creation controlled.

Audit trail

Timeline entries preserve meaningful case changes so staff can review the full path to a decision.

Safe callbacks

Dialog action tokens are owner-bound, permission-checked, one-use, and expire when stale.

Best-effort Discord

Webhook failures are logged while case workflows continue, and allowed mentions are disabled.

Configuration

Adjust the workflow without turning setup into a second project.

CoreCaseX ships commented YAML files for global settings, case types, Discord routing, visible text, and SQLite storage. Safe changes can be reloaded with `/case reload`.

How it works

From player report to final decision.

The current MVP keeps the workflow inside Paper: players submit cases through Dialog UI, staff triage them in-game, and SQLite stores the complete history.

1

Configure the case types

Enable the flows your server needs, set default priorities, and tune reason or category options.

2

Players open `/case`

Guided forms collect descriptions, choices, locations, death context, or target player details.

3

Staff triage the board

Use filters, claims, assignments, priority changes, notes, replies, and information requests.

4

Resolve, reject, or archive

Close the case with a final outcome, keep the timeline available, and archive completed cases.

Compatibility

Focused on the current Paper MVP.

CoreCaseX targets a single-server Paper setup today. That narrow scope keeps installation practical and avoids requiring extra services before your staff can start managing cases.

Runtime

Paper 1.21.11 or newer with Java 21.

Storage

Local SQLite database under the plugin data folder.

Notifications

In-game staff/player notifications and optional Discord webhook embeds.

Administration

Config reload, debug command, validation warnings, and commented default YAML files.
