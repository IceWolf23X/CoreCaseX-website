Configuration reference

Control CoreCaseX without guessing at behavior.

CoreCaseX uses commented YAML files for global limits, case types, Discord routing, messages, and SQLite storage.

Config Files

Runtime files live under plugins/CoreCaseX/: config.yml, case-types.yml, discord.yml, messages.yml, and storage.yml. Runtime case data lives under data/corecasex.db by default.

Global Settings

config.yml controls language identity, displayed case ID format, maximum open cases per player, submission cooldown, and staff notification switches.

case-id-format: "#{id}"
max-open-cases-per-player: 5
submission-cooldown-seconds: 60
staff-notifications:
  new-case: true
  player-replied: true
  assigned-to-you: true
  player-replied-scope: assigned-only

Case Types

case-types.yml controls enabled state, default priority, location collection, player report reasons, and bug report categories for the five built-in case flows.

grief-theft:
  enabled: true
  default-priority: HIGH
  collect-location: true

Discord Webhooks

Discord is disabled by default. When enabled, events can route by priority webhook, case type webhook, default webhook, or legacy fallback webhook. Delivery is best-effort and cannot block case workflows.

enabled: true
webhooks:
  default: "https://discord.com/api/webhooks/..."
events:
  case-created: true
  player-replied: true
  case-resolved: true

Messages and Dialog Text

messages.yml controls command feedback, validation text, player notifications, staff notifications, Dialog titles, body lines, inputs, detail rows, buttons, and hover text. Server-controlled text can use MiniMessage; player-provided placeholders are escaped before rendering.

Permissions and Commands

Player permissions default to true; staff and admin permissions default to op. Key commands include /case, /case list, /case view <id>, /case board, /case open <id>, /case claim <id>, /case assign <id> <staff>, /case priority, /case status, /case archive, /case reload, and /case debug.

Troubleshooting Quick Reference

  • If the plugin disables itself, confirm Paper 1.21.11+.
  • If /case does not open, check Paper runtime, plugin enable state, and corecasex.use.
  • If players cannot create cases, check creation permission, case type enabled state, open case limit, and cooldown.
  • If staff cannot see tools, check corecasex.staff.board and corecasex.staff.view.
  • If assignment fails, the assignee must be online.
  • If archive fails, resolve or reject the case first.
  • If Discord does not send, check enabled state, URL validity, event switches, routing order, and console warnings.
  • If evidence is missing, check evidence collection and staff evidence permissions.

Production Validation Checklist

Boot on Paper 1.21.11+, open /case, create each case type, inspect player and staff views, claim, assign, change priority, change status, add note, send reply, request info, reply as reporter, resolve, reject, archive, test teleport on location evidence, test Discord success and failure, and reload after a harmless wording change.
