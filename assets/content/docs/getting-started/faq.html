Platform and storage

Does CoreCaseX need a proxy or MySQL?

No. Version 2026.1.1 is a standalone Paper plugin using local SQLite.

Does it support Spigot?

No. Startup requires Paper 1.21.11+ and Paper Dialog APIs.

Where is the database?

The bundled default is plugins/CoreCaseX/data/corecasex.db. A safe relative path can be configured, but changing it requires restart.

Interface and workflow

Why does /case open an inventory?

That is the current design. Inventories handle navigation and choices; Paper Dialogs handle typed fields.

Can staff reassign a case?

Yes. Assign/reassign requires an online target and rejects resolved, rejected or archived cases. The inventory chooser lists online case-view staff.

Can a player open another player's case by ID?

No. Player detail access checks the stored reporter UUID. Staff use the separately permissioned staff open action.

Can a closed case receive replies or notes?

No. Normal replies, notes and workflow changes require an open case. Archive is available only after resolution or rejection.

Configuration and integrations

Does case-id-format change displayed IDs?

Not in the current 2026.1.1 source. The key is bundled but not read; configured messages contain their own ID formatting.

Can every case type control location collection?

Not uniformly. Support, bug and grief/theft use location choices/defaults. Player reports always attach current reporter location, while lost-item cases use the latest-death choice. See the exact key behavior.

Can Discord failure lose a case?

No. Discord is best-effort after case state is committed. Failures and non-2xx responses are logged.

How do I report a problem?

Use the public CoreCaseX Issues tracker and include the plugin, Paper and Java versions, relevant settings, storage context and reproduction steps.
