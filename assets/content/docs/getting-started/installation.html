Requirements

  • Paper 1.21.11 or newer with Paper Dialog support.
  • Java 21.
  • The current CoreCaseX-2026.1.1.jar from Modrinth.

Installation

  1. Stop the Paper server.
  2. Back up an existing plugins/CoreCaseX/ folder before replacing a build.
  3. Place the JAR in the server plugins/ directory.
  4. Start the server and confirm CoreCaseX enabled. appears without runtime-guard or SQLite initialization errors.
  5. Join with a permitted player and run /case. The inventory main menu should open.

Generated files

The plugin data folder contains five bundled administrator defaults:

plugins/CoreCaseX/
  config.yml
  case-types.yml
  messages.yml
  storage.yml
  discord.yml
  data/corecasex.db

The SQLite file is runtime data, not a bundled default. Do not delete it when regenerating YAML.

First test

  1. Create one support request as a normal player.
  2. Open the staff board and confirm that the case appears.
  3. Claim it, send a reply, request information and reply as the reporter.
  4. Resolve it and archive it.
  5. Enable Discord only after the in-game path is proven.

What to configure first

Start with the case limit and cooldown, enabled case types, staff permissions and notification scope. Keep the default SQLite path for the first validation. Review text and Discord routes after the workflow succeeds.

Safe rollout order

Use a staging server or a controlled staff test. A successful build or startup does not prove every inventory click and Paper Dialog path on your exact Paper release.
