Purpose

case-types.yml controls which built-in flows are available, their initial priority and the option lists used during guided creation.

Current bundled default

Shared schema

For each of support-request, player-report, bug-report, lost-items and grief-theft:

  • <type>.enabled: show or hide that creation flow.
  • <type>.default-priority: LOW, NORMAL, HIGH or URGENT. Invalid text warns and falls back to LOW for support, HIGH for grief/theft and NORMAL for the other types.
  • <type>.collect-location: intended location-choice default, with the actual per-flow limits below.

Option lists

  • player-report.reasons: inventory choices before the target/description Dialog. An empty list warns and falls back to Other.
  • bug-report.categories: inventory choices before the description Dialog. An empty list warns and falls back to Other.

Actual location behavior in 2026.1.1

TypeBehavior
Support requestcollect-location becomes the default value of a Yes/No inventory choice.
Player reportplayer-report.collect-location is currently not read. The reporter's current location is always attached.
Bug reportcollect-location becomes the default value of a Yes/No inventory choice.
Lost itemslost-items.collect-location is currently not read. An explicit latest-death choice controls death location/evidence.
Grief/theftcollect-location becomes the default value of a Yes/No inventory choice; manual location text remains available.

These limitations are documented rather than hidden. Do not rely on the two currently unused keys for privacy or evidence policy.
