Purpose

config.yml controls submission limits and in-game staff notification policy. It also contains two future-facing identity keys that are not active in 2026.1.1.

Current bundled default

Key reference

PathSemantics
languageReserved for future locale support. Current visible text is read from messages.yml; current Java source does not read this key.
case-id-formatBundled future-facing setting. Current Java source does not read it, so changing it does not change IDs in 2026.1.1.
max-open-cases-per-playerMaximum non-closed cases per reporter. Default 5; values below 1 clamp to 1 and warn.
submission-cooldown-secondsIn-memory delay between successful new cases. Default 60; 0 disables; negative values clamp to 0 and warn. State resets on restart.
staff-notifications.new-caseNotify online staff with case-view permission when a case is created.
staff-notifications.player-repliedEnable in-game staff notifications when the reporter replies.
staff-notifications.assigned-to-youNotify the online player who receives an assignment.
staff-notifications.player-replied-scopeassigned-only, assigned-and-staff or all-staff. Invalid text warns and falls back to assigned-only.

Player-reply notification scopes

  • assigned-only: use the assigned online staff member; if unavailable, fall back to online staff with case-view permission.
  • assigned-and-staff: include the assigned staff member and other eligible staff viewers.
  • all-staff: notify every online player with corecasex.staff.view.
