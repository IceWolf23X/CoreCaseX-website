Purpose

discord.yml controls optional best-effort webhook notifications. Discord is disabled by default and never owns case state.

Current bundled default

Enablement and routing

  • enabled: master switch.
  • webhook-url: legacy fallback.
  • webhooks.default: preferred fallback; wins over the legacy key.
  • webhooks.types.{support-request,player-report,bug-report,lost-items,grief-theft}.
  • webhooks.priorities.{low,normal,high,urgent}.
  • server-name: prefix used in the webhook username.

Route order is priority, case type, default, then legacy fallback.

Event switches

events.{case-created,urgent-created,case-claimed,case-assigned,status-changed,priority-changed,player-replied,info-requested,staff-replied,case-resolved,case-rejected}.

Embed colors

Decimal RGB integers under embed-colors.{created,urgent,claimed,assigned,status,priority,reply,info,staff-reply,resolved,rejected}.

Failure and payload behavior

Blank or malformed URLs are skipped. The validator accepts HTTP or HTTPS with a host; it does not restrict the host to Discord. Connection timeout is five seconds and request timeout is ten seconds. Non-2xx responses and asynchronous failures are logged.

Case operations are already committed before webhook publication. Payload text is JSON-escaped and truncated to Discord field limits, and allowed_mentions.parse is empty to prevent generated pings.
